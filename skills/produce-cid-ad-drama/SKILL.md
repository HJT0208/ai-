# 小G·通用AI广告短剧制作

把用户确认的故事转化为剧本、真实图片、分区提示词和供用户ComfyUI使用的逐段素材包。先保证因果、身份、动作和声音说明正确，再增加细节。按阶段读细则，不把本技能全文粘贴给视频模型。

## 默认职责边界：剧本与图片由助手制作，视频由用户ComfyUI生成

- 助手负责大纲、剧本、人物面部和造型设计、动作与表情描写、场景与商品图片的生成/修改、分镜、视频提示词、纯台词、声音表演说明、逐段Picture槽位、素材整理及自检；图片任务使用真实图像工具，不止交提示词冒充出图。
- 用户通过自己的ComfyUI执行广告视频生成。助手交付适用于该工作流的文字与图片；默认不连接服务器、不上传到视频节点、不提交/重试视频任务、不改在线节点或增强器、不操作队列、不负责生成或取回MP4。
- 每30秒分组、每5秒拆段是剧本/分镜/素材组织方式，不是助手启动算力的指令。用户说“制作广告短剧”“继续”“生成素材”不视为授权助手出视频；只有后来明确委托具体视频操作才启用相应独立执行分支。
- 默认流程在剧本、图片、提示词、槽位和自检完成后交用户验收与ComfyUI使用；不因未跑视频把已完成的素材交付判为失败。真实出片与听检属于后续验证，不冒充本轮已验证。
- 用户回传成片、报错、截图或工作流导出并要求检查时，在实际可读能力内分析并修正对应脚本/图片/提示词。给出节点填入说明不等于代替用户操作在线ComfyUI。

## 通用范围与配置

先读 [跨题材配置与路由](references/12-project-profiles.md)。使用同一制作骨架，按项目选择叙事模块；不把历史女主、丈夫、佳佳、背叛、复仇、素颜霜、门或树带入新项目。历史案例只用于缺陷回归。

- 每个项目重新定义商品/证据、受众、题材、角色、人物关系、叙事结构、场景、时代、画风、时长、声音和交付范围。
- 默认每30秒分组、每5秒一个生成段；项目明确授权时支持可变段长和尾段。没有人物的商品演示允许零角色、零对白，不强行制造冲突或反转。
- 区分固定质量规则、用户长期偏好和本次项目配置。默认无配乐、无品牌；本次明确要求覆盖默认，实际工具能力与真实商品证据始终核实。
- 两层工作流：本技能维护题材无关的制作SOP；执行时为真实模型/ComfyUI导出建立独立适配档。修改SOP不等于修改在线节点或已排队任务。

## 固定默认：全套技能与最新版已验收工作流

- 用户已于2026-10-25明确验收并要求固定沿用。本技能作为主线，人物与剧本资源库、优秀脚本标准及原七技能分工共同组成默认流程；真实出图调用图像生成技能和工具。用户提出新的广告短剧素材任务时自动采用，不再要求重复选择或提醒。
- 先查资源库，再用优秀脚本标准指导写作与自检；编剧、广告文本、分镜和图像按既定分工配合。按本次需求读取并应用相关技能，不为凑齐调用数量重复加工；音视频处理与文档动画只在对应明确需求中启用。
- 固定以最新版已验收工作流为基线；未验收草案不自动替换，技能更新也不覆盖项目禁改项。默认每30秒分组、每5秒拆段，只有用户明确要求才变更。
- 全剧锁定人物面部身份，服装随场景合理变化，连续事件保持造型与动作衔接；详细描写面部表情、身体动作与空间。纯台词、画面剧情、声音说明和整合提示词分别保存与复制，默认无配乐。
- 助手负责脚本、真实图片、分镜、提示词和动态Picture槽位；广告视频由用户ComfyUI生成。本固定约定不授权操作在线节点、队列或恢复旧任务。

## 七技能默认协作

创作前调用新增的 `manage-drama-resources`（小G·人物与剧本资源库）查找可复用的人物、真实图片和剧本版本；写作与交付自检调用 `apply-script-quality`（小G·优秀脚本标准）应用用户Word的六层结构。按 [资源库与脚本标准接入](references/14-resource-and-quality.md) 执行。原七技能保持分工，新两项分别提供资源和质量依据，不增加视频生成任务。

按 [技能分工与交接](references/13-skill-orchestration.md) 自动路由；七套技能纳入同一流程，按当前任务触发相关能力，不为凑齐数量重复加工。主技能统一维护项目事实、版本、槽位、声音、自检和交付。

- 大纲/剧本：DeepWhite 中文影视编剧 v1；广告钩子、卖点与口播：DeepSeek 短视频脚本生成器。
- 表演、空间、运镜及视频提示词：MadStory；静态人物/场景/商品图的中英提示词：DeepWhite 图像提示词，实际出图另外调用图像工具。
- 参考视频转写、字幕与获准音视频处理：media-skill；文档转文字字幕动画：DocToShortVideo，作为相应需求的独立分支。
- 每30秒分组、每5秒拆段保持默认；只有当前项目得到用户明确授权才改。沿用已给时长、受众、模型和音频限制，辅助技能的默认值不覆盖项目配置。
- 使用相应技能前读取其当前说明和本阶段必需参考；已读且未变更的内容复用。只在用户指定验收点或关键事实缺失时等待，不重复要求选择技能或逐步批准。

## 人物、表演与空间

使用 [人物造型](references/03-character-and-wardrobe.md)、[动作空间](references/04-blocking-and-performance.md)。

- 从人物资源库选择每个角色全剧共用的face_lock_id和按时段切换的wardrobe_lock_id；面部身份跨组/跨镜固定，换装、妆容和情绪不等于换脸。验图对照主要面部参考及服装参考分别核对，不让旧全身图的脸覆盖当前身份。

- 锁住骨相、五官拓扑、眼睛、发际线、发色、分缝和发长；仅按授权改变服装、鞋、妆面与皮肤表面状态。
- 不从不可读参考图虚构“相同面部指标”；用实际参考图和可见细节锁定身份。
- 表情写为起点→触发→变化→终点；选择眉眼、视线、唇、下颌、肩颈中的关键部位联动，避免全脸同时极端夸张。
- 分清自身左右手、画面左右、肩线、身体/头/眼朝向与摄影机位置；方向有要求的图不镜像。
- 写动作依赖：先完成前置事件再执行依赖动作；例如先解锁再打开、先放稳再松手、先组装再承重。历史离开和涂抹仅是对应项目的回归例。
- 遮挡场景用镜头、遮挡物、观察者与目标的相对位置及视线检验；按项目选择柱、门框、树干等物体，不默认加入偷窥情节。
- “只改一只手”时锁定其余构图、站位、人物、服装、光线、背景，不借机全图重做。

## 图像与槽位

使用 [图像生成](references/05-image-generation.md)；真生成/编辑时使用实际图像工具并先看参考图。

- 一图一个可见瞬间、一个独立文件，默认不拼图；无图仅交待生成提示词，不伪造PNG或零字节占位图。
- 区分身份图、服装图、布局图、表情图、商品图和起止帧，明确每图允许影响的内容。
- 每段按实际出场角色和资产用途重新绑定Picture0；角色不出镜就不占全片固定槽，不依据旧剧情的25秒等时间点分配。零角色演示按商品、结构、场景或手部参考选图；传图数量取决于本镜和真实节点能力。
- 文件、槽位、提示词、网页和实际节点同源；改槽位同步依赖，禁用本镜未用分支，不删除素材和旧任务。
- 参考图不等于强制首帧，不要求视频轮播静态肖像；首尾帧控制必须单独说明并核实工具支持。

## 声音与复制

使用 [声音对白](references/06-audio-and-dialogue.md)、[提示词契约](references/07-prompt-contract.md)。

1. 纯台词只含实际说出的字，不含角色名、括号、图号、时间码、情绪说明或“台词”标签。
2. 视觉、声音说明、纯台词、整合块分别保存与复制；整合块不送TTS/口播文本框。
3. 只有一个文本框时设置唯一发声区，压缩其他区；仍误读就用静音画面加独立配音，不无限叠加否定句。
4. 音乐通道默认空。逐镜枚举获准人声、动作/商品声效与必要环境声；新增声效必须进项目白名单，不能因为写实风格自动加底噪。
5. 无配乐不等于无音频；仅脚步声不称全程静音；全程静音的最终MP4要求无音轨。
6. voice_id/批准音频锁音色；节奏、音高、音量、气息、句尾和停顿分开描述。提高音高不自动喊叫。
7. 时间窗是导演目标而非逐帧保证；先试听台词实际时长，留动作反应空间。
8. 不承诺只靠提示词绝对禁配乐；真实节点配置、音轨控制、成片听检共同把关。

## 适配执行

准备ComfyUI填写说明时按需读取 [ComfyUI适配](references/08-workflow-adapter.md)。默认只根据用户提供的导出/截图适配交付素材；下列在线操作规则仅在后来另有明确视频操作委托时适用，不自动触发。

- SOP不冒充可直接运行的ComfyUI JSON；可执行图必须来自真实导出并验证节点、版本和连线。
- 记录当前节点、图号、音频连接、文本输入、分组模式及队列；不移植其他模型的参数。
- 增强器是可选支路；核对输出是否进入主流程后按授权临时停用，完成后恢复原模式，不一律Always。
- Llama decode错误先定位支路；区分历史任务与当前画布，不凭一句错误断定显存不足；字符数不是token数。
- 单镜不加载42,117字符整份说明书；核实文本、图片和输出的实际预算。
- 缩略图不证明服务器文件有效，下拉框空白也不证明历史任务缺图；核对任务快照与输入证据。
- 超时或重连先查任务ID和历史，不盲点运行；正常排队，不删、不停、不插队。
- 每阶段落盘进度、产物哈希和下一步；继续时读取检查点，仅推进未完成项，减少重读、重传、重复生成和额度浪费。
- 分清浏览器端与本地工作区文件路径；文件URL权限不等于文件系统互通。连接失败不自动诊断为缺权限。
- 用户取消后不恢复旧任务；报告遗留状态，等待真正的新授权。

## 工具与交付

读取 [项目契约](references/10-project-contract.md)，从 `assets/project-template.json` 建立真实项目。

```bash
python scripts/compile_project.py validate project.json
python scripts/compile_project.py build project.json --out delivery
python scripts/compile_project.py validate project.json --ready
python scripts/probe_media.py clip.mp4 --mode silence
```

`--ready`仅在真实图像齐全、参考素材已批准且语义复核后使用。脚本只能验证已编码条件，不能代替看片、听检或判断商品真实效果。

分类输出：规则大纲、30秒组、逐5秒脚本、分区提示词、逐镜槽位、实际图像、待生成图片提示词、音频与成片、质检记录。网页提供独立复制按钮。见 [质检交付](references/09-qa-and-delivery.md)。
只有本轮用户明确要求ZIP才打包；普通制作与离线演练均不自行追加压缩包，不因以往用户曾要过ZIP而沿用。

## 自检与迭代

- 按 [回归场景](references/11-regression-cases.md) 检查旧问题。
- 技术自检后作独立情景演练，再交用户验收；不保证永不串音、百分百锁脸或提示词已等于视频。
- 改动后同源重建受影响输出，检查前后承接；未授权剧情保留原文与版本。
- 说明改了什么、测了什么、哪些未实测，以及用户本次要检查哪些点。
