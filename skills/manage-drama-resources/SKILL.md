# 小G·人物与剧本资源库

先查资源再创作，先确认真实来源再入库。分开人物身份、造型、剧情角色和图片用途；同名不代表同脸，复用演员不自动复用旧剧情。

## 面部身份锁定

使用 [面部锁定与验图](references/face-lock.md)。每个人物的每个身份版本建立独立face_lock_id和唯一主要面部参考图，登记脸型/骨相、眉眼鼻唇、颌线、发际线与可见识别特征；造型、妆面和情绪分层。旧脸与后期指定脸分别锁定，不因同名混用。实际图像生成/编辑时传入原始参考图和当前面部锁定卡，不只靠文字描述。

优先沿用该项目已选锁定；存在不同身份候选且用户未指定时，只澄清选择，不自动以新上传或最清晰图覆盖。候选卡可归档但不冒充用户已批准。生成后逐图比对身份锚，发现五官漂移就标需返工，不承诺模型百分百锁脸。

同一项目为每个人物建立全剧共用的face_lock_id，跨30秒组和所有5秒片段沿用；前期/后期、情绪或换装不切换演员脸。只有用户明确改变身份才建新版。历史剧中前后脸不同的记录保留作证据，新制作须先选统一脸；旧全身图若脸不同只能提供服装/姿态，不与主要脸融合。

## 服装与配饰锁定

每个服装版本建立wardrobe_lock_id，记录款式、领口/袖长/裙裤长度、主色、材质质感、腰线、鞋型/鞋色/鞋跟、耳饰/项链、手包和持物左右手、发型及适用时间段。未核实属性写unknown，不凭小图编造细节。面部身份在全剧保持一致；服装按场景、时间、地点和活动安排，可跨场景改变，不要求全剧同一套衣服，也不为合理的新场景换装逐次请求批准。已锁服装不擅改，同一连续事件的前后镜头保持服装一致；脱外套等变化写清动作原因。

逐片段绑定character_id、face_lock_id、wardrobe_lock_id、表情与场景图。生成提示词同时引用独立面部图与服装图，并声明各自职责；服装图里的旧脸、笑容、灰背景不覆盖已锁身份。验图既查五官，也查衣服款色、鞋履、配饰、持包手与左右方向；修一项时锁住其他项，保存新版本和已知瑕疵。

## 动作与面部提示词细化

按 [详细动作与面部描述](references/detailed-prompts.md) 写到可执行。动作明确谁、用哪只手、从哪里出发、怎样移动与接触、速度和力感、身体重心、先后依赖及结束状态；面部把固定五官身份与变化表情分开，明确触发、眉眼视线、眼睑、唇颌、肩颈、变化过程和收束，不用“生气”“同一个人”代替细节。详细导演稿与精简执行稿同源，静态图只选一个可见瞬间，不能把连续动作塞成一张图。

## 查询与复用

1. 读取 `assets/catalog.json` 的coverage、项目、人物与图片索引；先看项目索引；需要完整原剧本/提示词时，按索引source_snapshot或full_script_source_id从Library读取对应已保存快照，再选所需片段，不整库灌入提示词。按 [入库与复用契约](references/resource-contract.md) 判断来源和状态。首批导入不等于全部历史已收齐。
2. 明确复用方式：原人物原造型、同人物换装、只复用演员外貌、新角色借鉴、只复用场景/构图、原剧本续写或仅借鉴结构。有明确指令直接执行；多个候选会改变脸或造型时只澄清该歧义。
3. 用 `python scripts/resource_store.py search '佳佳'` 检索，再按稳定ID、项目、身份版本、造型、角度、用途和状态选择。默认优先明确批准记录；草稿/历史待核记录显示状态，不静默替代批准版。
4. 实际用图时按Library技能取回真实图片并看图，核对哈希、尺寸、身份和朝向。图片缺失时标待图并继续可完成的文本，不重生替身冒充旧图。不得仅凭文字目录声称已看图。
5. 明确每图控制脸/身份、衣服、表情、布局、商品或起止帧。灰背景、静态微笑、站姿和旧关系不自动进入新剧情；跨项目复用人物要重新定义姓名、关系、服装、场景和商品。
6. 同人换装新建造型版；五官变化建立身份版，保留旧图。多个历史女主脸有差异时按目录身份版本选择，不拼脸、不承诺共享人物ID就必然一致。局部修改锁住其余区域。
7. 将选中人物ID、身份版本、真实图片ID、用途和禁改项交主技能；编剧写剧情、MadStory写动作与视频提示词、DeepWhite图像技能写静态中英提示词、真实图像工具出图。剧情与纯台词继续分区。

## 创作过程中的归档

- 用户已授权维护资源库。后续制作开始先查库；取得新人物、真实图片、剧本或实质修订后，在该任务内登记并保存进度，不逐条重复请求归档授权。任务结束后不声称后台扫描聊天。
- 图片先按Library技能保存，拿到准确Library ID后再登记。相同文件ID或SHA256复用已有记录，避免重复上传。不删除或覆盖用户原图；不把暂存路径、签名URL、base64或密钥写入长期目录。
- 只把用户明确批准的版本标approved；来源文件存在、离线检查通过都不等于批准。草稿可归档，但保留状态与证据。版本的前后承接、纯台词和导演说明分别保存。
- 把剧本和提示词写成按项目/版本组织的文本或JSON快照。用脚本put更新索引，保留历史并校验引用；按技能修改规范只提交本技能目录并推送。失败保留本地成果，如实报告未完成保存。

## 命令与交付

```bash
python scripts/resource_store.py validate
python scripts/resource_store.py search '酒红'
python scripts/resource_store.py show characters char-shen-zhiqiu
python scripts/resource_store.py put characters /absolute/record.json --expected-revision 1
```

提供真实来源、版本、批准状态、可复用用途和缺失项。用户要图片时交真实图片文件，不把技能目录或索引当图。只辅助剧本、图片与提示词，广告视频由用户ComfyUI生成，不提交队列。技能创建不附ZIP或sandbox技能文件。
